# 汪汪钱包

独立实现的 Flutter Android 日常记账应用，当前版本 0.3.1。

![汪汪钱包 Logo](assets/brand/wangwang-wallet-logo.png)

支持 Android 7.0 及以上的 ARM64（64 位 Android）设备。发布标签为 `v0.3.1`，Android 构建号为 `10`。
应用标识为 `io.github.donia257.gougouwallet`。
0.3.1 增加内置中文图片识别，默认仅发布 ARM64 安装包，版本记录见 [CHANGELOG.md](CHANGELOG.md)。

## 功能

- 人民币收入、支出与转账，支持日期、具体时间和备注。
- 记账页只在首次进入时聚焦金额，返回选择面板后不再自动弹出输入法；“记一笔”按钮滚动后自动靠右收起为加号。
- 日常页展示月收支、预算、记账天数与今日概况；账单页按日期分组查询和编辑明细。
- 沉浸式状态栏，四个主页滚动后收起为 Logo 与名称居中的渐变玻璃页眉，底部导航使用圆角毛玻璃背景。
- 每日账单使用完整圆角卡片，统一筛选控件、按钮与中文字体。
- 连续记账、复制账单、编辑删除，以及日期范围、账户、分类组合筛选。
- 单层一行筛选栏默认显示全部类型、全部日期、全部账户、全部分类；日期默认查询全部历史，选择后直接展示所选内容。
- 日期提供今天、近三天、本周、本月、本年与跨月自定义日历；记账时间使用可循环滑动的 24 小时时、分滚轮。
- 分类、账户、收支类型、年月选择统一使用圆角面板；预算展示剩余天数（含今天）的日均可支配金额。
- 分类添加、改名、图标、拖动及菜单排序，删除已使用分类时迁移历史账单。
- 月收支、结余、分类占比、每日支出趋势、月预算与超支提示。
- 设置页提供分类、预算、备份恢复、GitHub 检查更新与应用信息。
- SQLite 本地存储，JSON 完整备份，最近 5 份本机恢复快照。
- 微信与支付宝 CSV / XLSX 账单导入，支持 UTF-8 / GBK、预览、选择账户、逐笔或批量分类、重复识别和按批次撤销。
- “记一笔”滑动挂起后以 55% 不透明度显示，挂起满 10 秒自动恢复完整按钮与不透明显示。

## 图片识别记账

在“记一笔”或编辑账单页，点击右上角“图片识别”图标，选择本机支付截图或小票。内置 ML Kit 中文模型，首次使用即可离线识别，无需下载模型或安装 Google Play 服务。单张图片不超过 20 MB，优先使用清晰截图；大图会先缩采样，支持 EXIF 方向修正。

先核对金额候选、收入/支出类型、推荐分类、商户备注与日期，再点击“填入记账页”；该步骤只填表，仍需手动点击保存才写入账本。账户沿用原选择，无法识别的日期保留记账页日期。分类使用现有稳定分类 ID，支持人工修改，并提示同日同类型同金额的潜在重复记录。

识别规则优先参考实付、支付金额和合计，降低优惠、原价、余额等字段的优先级。退款、转账和未完成交易提示人工核对，不自动套用普通收支。OCR 可能漏字或读错数字，不保证所有截图、小票格式都能准确识别。图片不上传至服务器，不作为账单附件写入数据库或完整备份；系统文件选择器可能保留临时缓存。

识别服务、文字解析和核对界面分开实现。文件读取/大小检查、交易日期解析、兜底分类及分类推荐规则供导入和 OCR 共用，避免各入口维护重复规则。原有 CSV / XLSX 导入、批次撤销与 version 3 备份格式继续兼容。

## 安装包与架构约定

本项目从 0.3.1 起，除非用户明确另有说明，默认只构建、分发 ARM64 安装包。Gradle 排除其他架构的 JNI 文件，`tools/dev.ps1` 明确指定 `android-arm64`，构建完成后自动检查 APK 的实际 ABI。普通 x86 模拟器与 32 位 Android 设备不能直接安装；开发运行应连接 ARM64 设备，或使用支持 ARM64 转译的测试环境。

保留中文字体和完整中文 OCR 模型，使用代码压缩、资源裁剪和单架构打包减小体积。0.3.1 签名 APK 约 40.7 MiB，0.3.0 三架构通用包约 64.5 MiB，约缩小 37%。这是不同架构打包策略下的实际总包对比，不代表 OCR 本身减少了体积。

## 微信与支付宝账单导入

入口为“设置 → 数据与备份 → 微信 / 支付宝账单导入”。下载个人对账用途的原始账单，先解压，再选择 CSV 或 XLSX 文件；不支持 ZIP、PDF 和旧版 XLS。每个文件不超过 20 MB、5 万行，XLSX 解压内容限制为 80 MB。

文件在本机解析，先展示可导入、待核对、重复、已排除和异常项，再确认追加到现有账本。可指定入账账户，默认分类为“其他 / 其他收入”，支持逐笔或按收支类型批量调整。支付平台不一定等于实际扣款账户，多账户流水可分次勾选导入。

有交易号的流水按“平台 + 交易号”去重；缺交易号以及与已有账单同一分钟、同类型、同金额的记录默认不选，需手动核对。交易号已被表格软件改写的记录会标为异常，建议使用原始导出文件。微信与支付宝之间没有共同交易号，不自动判断跨平台重复或内部转账。

退款相关流水（包括显示已退款的原消费）、关闭/失败/未完成交易、不计收支、可识别的充值提现及理财等资产变动不自动入账，预览中说明原因。未知状态列为异常。0.3.0 尚不提供自动关联退款，请核对原消费，避免直接把退款计为收入。

导入前在同一事务中保存恢复快照；写入失败不会留下半批数据。导入记录保存文件名、时间及批次，可单独撤销：删除该批次现存账单，包括导入后对这些账单的修改，保留其他批次、手动新增和复制的记录。撤销前显示现存及已修改笔数。手动删除某笔导入账单仍保留该交易的去重信息，撤销其批次后才允许重新导入。导入记录、去重及撤销信息均随完整 JSON 备份保存。

新版可读取 version 1/2 旧备份，新增的 version 3 备份需要使用 0.3.0 或更新版本恢复。

## 覆盖升级

v0.3.1 沿用原应用标识、签名与 version 3 账本格式，可在 ARM64 设备上直接覆盖安装 v0.3.0，保留流水、分类、账户、预算、导入批次和撤销信息。

v0.3.0 沿用原应用标识和发布签名，可直接覆盖安装 v0.2.5；启动时为 version 2 账本创建迁移快照并升级为 version 3，旧账单、分类、账户、预算和最近使用账户保持不变。Android 15 模拟器已验证这一升级路径。

v0.2.0 使用与 v0.1.0 相同的应用标识和发布签名，直接安装新版 APK 即可覆盖升级。
启动时读取旧版 `daily_ledger.db`，在迁移前保留原账本快照，再将分类名称映射为稳定 ID。
旧账单的金额、日期时间、备注、账户关联、初始余额和预算均参与迁移校验。
设置中的“从文件恢复”支持 v0.1.0 JSON 备份。

已完成真实旧版 SQLite 数据库迁移及事务回滚测试，并在 Android 15 模拟器上安装
v0.1.0 发布包、录入数据、覆盖安装 v0.2.0 发布包进行核对。
模拟器同时验证了系统文件选择器导出备份、导入旧版 JSON，以及从本机快照恢复账本。

## 开发

当前使用 Flutter 3.47.9、JDK 17 和 Android SDK 36。

```powershell
flutter pub get
flutter analyze
flutter test
flutter run
flutter build apk --debug --target-platform android-arm64
```

开发工具放在被 Git 忽略的 `.tooling` 中。可以使用
`.\.tooling\flutter\bin\flutter.bat` 调用当前工作区安装的 Flutter。

当前 Windows 环境使用 `tools/dev.ps1` 自动配置本地工具链及英文路径入口。

```powershell
.\tools\dev.ps1 -Command analyze
.\tools\dev.ps1 -Command test
.\tools\dev.ps1 -Command apk
.\tools\dev.ps1 -Command release
.\tools\dev.ps1 -Command run
```

英文入口位于用户目录 `wangwang-wallet-work`，指向原项目。
Gradle 缓存位于用户目录 `.codex/toolchains/wangwang-gradle`，避免中文路径导致 Kotlin 编译失败。
构建依赖使用 Flutter 中国镜像，当前机器的 Gradle 缓存配置了阿里云 Maven 镜像。

## 数据规则

金额使用整数分存储。转账是一条同时关联两个账户的记录，不参与收支和预算计算。
每次保存将完整账本快照写入 SQLite 事务，成功后再更新界面。
日期分组后的账单使用按需构建的滚动列表，自动化测试覆盖 1 万笔记录的查询和显示。
每日首次修改、版本迁移及恢复备份前生成恢复点，保留最近 5 份有效快照。

备份恢复完整校验后，经过确认替换当前账本。备份为明文 JSON，限 20 MB。
卸载应用或清除应用数据会丢失本地账本，请先导出备份。
应用关闭 Android 系统自动备份。正式发布构建从被 Git 忽略的 `android/key.properties`
读取签名配置。当前机器的签名密钥位于 `.tooling/signing`，密码和密钥仅保存在本机。
请另行安全备份签名目录及配置，后续版本需使用同一密钥签名才能覆盖安装。
